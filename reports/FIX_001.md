# Fix 001 — Combo Sim-Freeze Regression

Date: 2026-08-18. Correctness fix in the cinematic view (presentation only). No
gameplay/determinism impact.

## Bug
Polish 002 set the mid-combo hit-stop to a flat `0.02 s / speed`, which is smaller
than the per-hit frame `step` (0.031–0.052 s at 1×). The sim clock only stays
frozen while `_hitstop > 0`, so each hit left a ~0.01–0.03 s window where the clock
un-froze — over a long combo the replay could advance to the **next** attack event
and start a second combo coroutine before the current one finished (overlapping
combos, interleaved visuals). The intended "hold the sim clock across the combo"
guarantee was broken by the tuning pass.

## Fix (`BattleReplayView.cs`)
- Mid-combo hit-stop now `step + 0.02 s`, so the freeze always covers the wait and
  the sim clock stays frozen for the entire combo — one combo resolves before the
  next event fires. The visual cadence is unchanged (still driven by the
  accelerating real-time `step`).
- Dodge beat freeze bumped to `0.16 s / speed + 0.02` to close the same sub-step gap.
